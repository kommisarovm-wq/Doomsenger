# AGENTS.md

## Architecture
Static single-page site. Everything lives in `index.html`: styles in `<style>`, behavior in an inline `<script>`. No framework, no bundler, no build step. `netlify.toml` publishes the repository root. Server code: `netlify/functions/reply.mts` (`POST /api/reply`) generates contact replies via Netlify AI Gateway (Anthropic SDK); personas live in its `personas` map. `netlify/functions/account.mts` handles accounts in Netlify Database (Drizzle, schema in `db/schema.ts`, migrations in `netlify/database/migrations/` via `npx drizzle-kit generate --name …`): `POST /api/auth/code|register|login|logout`, `GET/PATCH /api/me` (nick, about, photo). There are no passwords: `/api/auth/code` (`purpose: login|register`) sends a 6-digit SMS code via SMS.ru (env `SMSRU_API_ID`), stored hashed in `phone_codes` (5 min TTL, 5 attempts, resend after 60 s); login takes `{ phone, code }`, registration takes the form fields plus `code`. Phones are normalized to `+7…` by `normalizePhone()`; sessions are random tokens in the `sessions` table, sent as `Authorization: Bearer`.

## Screens
- `#screen-register` — auth screen: `#auth-choice` with «Вход»/«Регистрация» buttons, `#login-box` (phone + code) and `#register-box` forms; both use a two-step submit: the first press calls `requestCode()` and reveals the `.code-group` field, the second submits with the code (`resetCodeStep()` hides it again when the phone changes); `showAuth(box)` switches them with the `.pop-in` animation. On success the token is stored in localStorage (`doomsenger-token`) and `enterApp()` fills `user`; on load a saved token restores the session via `/api/me`. Profile edits call `saveProfile()`. `#logout-btn` («Выход из аккаунта», tab «Аккаунт») ends the session, resets chats and returns to `#auth-choice`.
- `#screen-main` — Telegram Web-style two-pane layout. Left `.sidebar`: header with CSS-drawn cat (glowing eyes) and chat search, then the chat list rendered from the `chats` array (empty state when there are none). Right `.chat-view`: the "doomsenger" title with a hint; clicking a chat (`openChat()`) highlights it, shows its name in the right pane header, its messages (`renderMessages()`) and a `#composer` input for sending. Messages are kept in memory in `chat.messages` (`{ text, time, fromMe }`); sending updates `lastMessage` and calls `requestReply(chat)`, which marks the user's messages as `seen` (the last own message gets a semi-transparent `.seen-label` «просмотрено» below it), shows a «печатает…» bubble and inserts the incoming reply (`.message.incoming`). The composer has a smiley button (`#emoji-toggle`) that opens `#emoji-panel`, an iPhone-style emoji keyboard (categories in `emojiCategories`, «Часто используемые» kept in localStorage, backspace key); emoji are rendered as Apple images from the `emoji-datasource-apple` CDN via `appendEmojiText()` (falls back to the system glyph), and messages of only 1–3 emoji get `.jumbo`. `#message-input` is a `contenteditable` div (not an `<input>`) so emoji show as the same Apple images while typing: read it with `getInputText()` (images → their `alt`), write with `setInputText(text, caretPos)`; typed/pasted emoji are converted on `input`, Enter submits. Chat-list previews also use `appendEmojiText()`. Below 720px only the sidebar is shown; opening a chat adds `.chat-open` to `#screen-main`, which shows the chat full-screen with a back button. `#screen-main` must start as `display: none`; the script switches it to `flex`.

- Profile page (`#profile-page`, opened by the header `#profile-avatar`): the big avatar is an `#avatar-picker` button with a camera badge that opens the hidden `#avatar-file` picker; the chosen image is center-cropped to a ≤400px JPEG data URL in `user.photo` (in memory) and `fillProfile()` shows it on both avatars via `.has-photo`. The «Ник» tab (`#nick-form`) edits `user.nick` (defaults to «Имя Фамилия» on registration); it is the name shown in the profile header and the source of the avatar initials.

## Conventions
- UI text and code comments are in Russian; keep it that way.
- Theme colors are CSS custom properties in `:root` (`--accent` is the orange eye color).
- Chats live in the `chats` array in the script and are rendered by `renderChats()` (add via `addChat({ name, lastMessage, color })`). The array starts with a «Мама» chat. With an empty array, the `#no-chats` empty state is shown. Search is always enabled; the query is split into words and a `.chat-item` matches if its text content contains every word (no matches → `#no-results`).

## Notes
Accounts live in Netlify Database; messages are still in memory. If more persistence is added, keep using Netlify primitives rather than external services.
